# SEO and accessibility improvements

- **Status:** done
- **Created:** 2026-11-01
- **Source:** /ask: "is there anything that we can do to improve SEO or acessibility"

## Goal
Bring the Indonesian and English pages closer to WCAG 2.2 AA while preserving the existing visual identity, and strengthen search/social understanding through clearer document semantics and complete metadata. The live figures must remain accurate, usable without JavaScript, and unchanged in their underlying calculations.

## Context
The site already has a strong technical SEO base: localized titles/descriptions, canonical URLs, reciprocal `hreflang`, Open Graph/Twitter cards, Dataset/FAQ JSON-LD, static fallback figures, and generated sitemap/robots files (`templates/index.id.html:2-33`, `templates/index.en.html:2-33`, `scripts/build-state.js:185-245`, `scripts/build-state.js:247-277`, `scripts/build-state.js:417-437`). These should be retained; FAQ structured data does not guarantee a search rich result.

The main gaps found during exploration are:

- There is no skip link or `<main>` landmark. The only `<h1>` contains the numeric debt amount, while the descriptive page title is a `<div>`; card labels and FAQ questions are also generic `<div>` elements (`templates/index.id.html:35-80`, `templates/index.id.html:85-137`, `templates/index.id.html:246-273`, with equivalent English markup).
- Both tickers update indefinitely with no pause mechanism. Reduced motion merely slows the main counter and removes interest jitter (`assets/app.js:8`, `assets/app.js:84-102`). Copy-button feedback changes button text without a dedicated live status (`assets/app.js:34-62`).
- The SVG has a useful localized label, but its accessible summary does not expose the historical values; only latest values and changes are available nearby (`scripts/lib/chart.js:146-161`, `templates/index.id.html:183-214`).
- Global link styling removes underlines, with no non-color hover/focus cue for inline prose links (`assets/style.css:88-89`). There are no explicit `:focus-visible` styles, and several small navigation/source links lack the generous targets already used by buttons and chips (`assets/style.css:112-120`, `assets/style.css:337-342`, `assets/style.css:544-554`, `assets/style.css:610-623`).
- At a 320px viewport, page padding leaves roughly 288px, but card/support grids require 320px and the methodology grid requires 300px; the unwrapped header can also overflow (`assets/style.css:79-101`, `assets/style.css:298-304`, `assets/style.css:517-524`, `assets/style.css:633-640`).
- A local OKLCH-to-sRGB contrast calculation found accent text on card surfaces at about 4.22:1, `--dim-2` on surfaces at about 4.09:1, and `--dim-2` on the page background at about 4.37:1. These affect small card/source links, section counts, and chart legend units; normal text requires 4.5:1 (`assets/style.css:48-69`, `assets/style.css:292-296`, `assets/style.css:337-342`, `assets/style.css:425-427`).
- Social images have dimensions but no localized `og:image:alt` or `twitter:image:alt`; the JSON-LD graph has datasets and FAQ entries but no WebSite/WebPage nodes tying the localized pages together (`templates/index.id.html:13-25`, `scripts/build-state.js:201-244`).

All source changes must be made in `templates/`, `assets/`, and `scripts/`; `public/` is generated output. The repository has no dependencies or browser-DOM test harness, and its existing tests use `node:test`.

## Non-goals
- No visual redesign, content marketing strategy, backlink campaign, keyword stuffing, or ranking guarantees.
- No changes to debt math, data sources, reporting cadence, analytics, caching policy, sitemap/robots behavior, or deployment.
- No new npm packages, accessibility overlay, chart library, templating system, or browser-test framework.
- No direct edits to generated `public/*` files.

## Approach
Make focused semantic and interaction improvements at their existing ownership boundaries, with Indonesian/English parity and minimal visual change. Add native controls—a pause/resume button and an expandable `<details>` data table—rather than custom widgets. Use generic, non-volatile social-image alt text, and enrich the existing JSON-LD graph rather than introducing duplicate metadata.

Alternatives considered and rejected: reduced-motion-only handling would leave other users without a way to pause indefinitely updating content; a richer chart label alone would still omit most historical values; visually hidden full data would be less useful to sighted keyboard users; global palette changes would disturb the design and could reduce button contrast; sitemap `lastmod` based on weekly generation would overstate content freshness.

## Implementation quality
- **Responsibility and integration:** Both `templates/index.*.html` files own document structure and localized control wording. `assets/app.js` owns ticker intervals and copy feedback. `assets/style.css` owns focus, reflow, target, contrast, skip-link, and native-details presentation. `scripts/lib/chart.js` owns chart rendering and its tabular alternative; `scripts/build-state.js` supplies localized tokens and JSON-LD. Generated files remain build outputs only.
- **Reuse and boundaries:** Reuse existing `.btn`, `.eyebrow`, `.counter`, `.card-label`, `.faq-question`, design tokens, `humanDate()`, `fmt1dp()`, and chart-series data. Add a chart-table renderer only because it shares the chart's formatting/escaping responsibility and can be unit-tested; do not add a general DOM abstraction or a new test seam for ticker behavior.
- **Testability and behavior:** Extend `scripts/lib/chart.test.js` to prove every quarterly row and localized value appears exactly once in the single accessible table and that text is escaped. Verify pause/resume, reduced-motion startup, live copy feedback, landmarks, keyboard operation, and reflow as observable browser behavior; do not couple tests to interval implementation details. Check built HTML for one descriptive H1, one main landmark, localized metadata, valid JSON-LD references, and matching table data.
- **Design constraints:** Preserve the handoff's colors, typography, spacing, and layout except for deliberate accessibility deviations: focus-visible skip link, visible pause/details controls, accessible focus indicators, prose underlines, larger link targets, and small-screen wrapping. Reset default heading margins where changing `<div>` to headings would otherwise alter layout.

3. `assets/style.css` — Add a reusable visually hidden utility and a skip link that becomes visible on focus. Add high-contrast `:focus-visible` outlines without removing defaults elsewhere; underline inline prose/source links (or otherwise provide a persistent non-color cue) while leaving button-like controls intact. Increase small navigation/source/footer link targets to at least WCAG 2.2 AA's 24px minimum with adequate spacing. Use `--accent-hover` for small accent links on card surfaces and `--dim` or a verified compliant token for section counts/chart legend units; do not change the accent button background pairing.
4. `assets/style.css` — Prevent reflow overflow by using bounded grid minimums such as `minmax(min(320px, 100%), 1fr)` for card/support grids and the equivalent for the 300px methodology grid; allow the header/navigation to wrap cleanly at narrow widths. Preserve 44px primary buttons/chips, avoid introducing horizontal page scrolling at 320 CSS px, and style the new details/table so only the data table may scroll locally if its two-dimensional layout requires it.

Reveal it only after `state.json` loads successfully. Start paused with the server-rendered official figures when `prefers-reduced-motion: reduce` is active; otherwise start live updates. Pause must clear the visual update interval without affecting hourly staleness checks, resume must render immediately before restarting, and switching to reduced motion while open must pause without later auto-resuming. Keep the counters out of live regions so they do not announce every tick.
6. `templates/index.id.html`, `templates/index.en.html`, and `assets/app.js` — Add one localized `role="status" aria-live="polite"` feedback element for copy/share actions. Announce successful copying alongside the existing temporary button-label change; distinguish user cancellation from actual clipboard/share failure and announce genuine failures without adding an error panel. Preserve synchronized button labels and the existing timeout behavior.
7. `scripts/lib/chart.js`, `scripts/lib/chart.test.js`, `scripts/build-state.js`, `templates/index.id.html`, and `templates/index.en.html` — Add a localized, escaped renderer for a complete quarterly table (date, government external debt, total national external debt, USD billions) using the existing series and formatting helpers. Expose it once beneath the chart through native `<details>`/`<summary>`, with a caption and scoped column headers; retain the existing localized SVG `role="img"` label and connect the chart to its textual alternative with `aria-describedby` where appropriate. Add focused `node:test` cases for row coverage, localization, single-table rendering, and escaping.
8. Run the standard tests/build, inspect both generated language pages, and perform the manual browser and metadata checks below. Confirm the diff contains only intended source changes plus regenerated `public/` output; do not hand-edit generated files.
9. `assets/style.css` — Give `.btn--secondary` an explicit `background: transparent` so the Pause/Resume label never falls back to a light UA `ButtonFace` behind near-white text. Keep the existing border, padding, and hover treatment; verify normal, hover, and focus-visible text/background and focus/adjacent-color contrast in both languages.
10. `assets/style.css` — Add `color: var(--accent-hover)` to the existing `.sources-list a` rule, matching the compliant treatment already used by `.card-source`. Confirm the 13px source links on `--surface` reach at least 4.5:1 without changing the global accent token or primary-button pairing.
11. `scripts/lib/chart.js`, `scripts/lib/chart.test.js`, `scripts/build-state.js`, `templates/index.id.html`, and `templates/index.en.html` — Move the chart description association from the generic wrapper `<div>` onto each generated `role="img"` SVG. Remove the two wrapper attributes in each template, retain the single description element and single details/table, and add a focused test for the SVG attribute and escaping while leaving callers that do not supply the argument unchanged.

Preserve synchronized labels, the 2.2-second revert, silent `AbortError` cancellation, genuine failure announcements, and all ticker behavior.

## Assumptions
- WCAG 2.2 AA is the accessibility target; if the project later chooses a different target, contrast and target-size checks in steps 3–4 should be adjusted explicitly rather than silently.
- The comprehensive interaction defaults are a visible pause/resume control and a visible expandable chart-data table. If visible additions are later rejected, steps 5 and 7 require a new design decision rather than hiding equivalent functionality by default.
- The existing static OG image remains representative of the page; generic alt text avoids duplicating figures that can become stale. If the image design changes, only the alt-token wording in step 2 needs revisiting.
- Native `<details>` is sufficient for the chart table; if supported-browser requirements disallow it, step 7 becomes a localized button-controlled region with equivalent keyboard and expanded-state semantics.

## Needs your decision
None.

## Risks
- Heading conversions can introduce browser-default margins and accidentally change the handoff layout unless explicitly reset.
- Pausing the wrong interval could stop staleness updates, while calling the initial tick in reduced-motion mode could replace official figures with estimates before the user acts.
- A toggle that changes both its accessible name and pressed state can be confusing; use an action button whose name changes between localized Pause and Resume, not a conflicting `aria-pressed` pattern.
- Copy/share cancellation must not be reported as a failure, and rapidly changing counters must not be placed in the polite live region.
- The wide and narrow SVGs are alternate presentations; the accessible table must appear once, not once per SVG.
- Color adjustments must preserve at least 4.5:1 for small text and 3:1 for meaningful graphics/focus indicators; borderline computed values should be confirmed in the browser.
- JSON-LD cross-references must use absolute, stable IDs and remain valid in both languages; structured-data enhancements should not be treated as guaranteed ranking changes.
